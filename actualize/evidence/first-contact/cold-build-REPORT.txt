FRICTION POINTS
---------------
Severity is the impact on a newcomer following the page. Quoted text is from the page or the skill.

F1 [HIGH] Contradiction between skill references: cognate-api.md, section "Gaps", says
   "No published @godspeedai/* npm packages yet (DEBT-016); every app is built from a local checkout".
   The page says the npm path works, and it does (6 packages installed). An agent that reads this section
   would refuse the page's path. Fix the skill text, not the page.

F2 [HIGH] Page sentence: "Starting from a project template with cognate create currently needs a copy of the Cognate source.
   This path doesn't." The skill's workflow step 3 says: "For a new app, generate a starter with `cognate create`".
   The page is honest about the gap, but it gives no route for the agent. The skill's own recovery text is:
   "If it asks for a Cognate source checkout, tell it to use the published npm packages." That does not say
   how to build without a starter. I had to infer hand-composed createRuntime from cognate-api.md section 2.
   Copy fix: add "Your agent will wire the app directly from the npm packages (no generator)." Also add to the
   skill: a no-generator recipe with the package list.

F3 [HIGH] Prerequisites are incomplete. Page Step 1 lists "Bun 1.4 or newer, git, Node.js and a coding agent".
   But the deriving-interaction-domain-models skill says it "Requires ... the DomainForge CLI", and the
   domainforge-sea skill assumes a `domainforge` binary. The page never mentions DomainForge or Rust/cargo.
   A newcomer without the binary hits a blocker inside Step 3. Here the binary was already present
   (domainforge 0.19.0 at ~/.cargo/bin). I did not time a cargo install; the domainforge-sea skill
   suggests `cargo install --path domainforge-core`, which needs a repo checkout. That is a second blocker for
   a newcomer. Copy fix: add a Step 1 line "DomainForge CLI (installed by your agent with cargo)" and
   state the Rust requirement, or drop the requirement.

F4 [HIGH] Version drift. cli.md says "current line: 0.1.x" and suggests `bunx @godspeedai/cognate-cli@0.1`.
   npm has 0.5.0 for every @godspeedai/cognate-* package. The skill's pin would point at a line that doesn't
   exist in the registry. Also, @godspeedai/domainforge is 0.21.1 on npm, but cognate-domainforge pins 0.19.0.
   Fix the pin text in cli.md.

F5 [HIGH] The IDM step is far heavier than the page implies. The page says only "Ask your agent" and
   "Build your first app". The skill (deriving-interaction-domain-models, output-and-validation.md) requires
   seven deliverables: a .sea model, a source translation map, a journey catalog, an interaction grammar summary,
   an assumptions/unknowns file, a validation report, and a handoff, plus a canonicality conclusion. I produced
   only the .sea file, the validation output, and validate.json. The rest is not written (partial completion).
   Copy fix: say "Your agent will first write a small domain model in .sea (budget ~10 minutes), then the app."
   Consider a skill flag for a "minimum viable IDM".

F6 [MEDIUM] .sea syntax gaps the skills don't state (cost four validate attempts):
   a. `Flow ... quantity 50 "USD"` does not parse (syntax error at the unit literal).
   b. A Flow's endpoints must be Entity declarations, not Role declarations. The skill's example implies roles.
   c. A Policy that compares a unitless quantity with "USD" evaluates UNKNOWN and fails validation.
   d. domainforge fmt --check flags a file that validates. The skill mentions this defect but not that it blocks
      the check step in the skill's "Evidence Requirements".

F7 [MEDIUM] The package set is not named anywhere a newcomer would look. Page: "Use the published
   @godspeedai/cognate-* packages from npm". cognate-api.md shows the imports but no install list. I guessed six
   packages. Copy fix: list the exact packages in the page or skill, e.g.
   "bun add @godspeedai/cognate-runtime-bun @godspeedai/cognate-kernel-api @godspeedai/cognate-runtime-api @godspeedai/cognate-client @godspeedai/cognate-domainforge".

F8 [MEDIUM] Stale or dangling references in the skill. idm-to-cognate.md points at `.agents/skills/...`, `docs/...`,
   and "ADR-0012" paths that exist only in a Cognate checkout. The skill also says `cognate dev` loads `domain/*.sea`,
   which doesn't apply to a hand-composed app.

F9 [MEDIUM] The step-3 "It failed" recovery text is the only guidance for an agent that goes off-path. It did not
   help me directly, because I did not need it. An agent that follows the skill literally would hit F2 and stop.

F10 [LOW] Page Step 2 says "Run both commands in an empty folder". The first command is a three-part chain
   (mkdir && cd && git init), so "both" is ambiguous. Clarify the wording.

F11 [LOW] bunx is absent on this machine. The page's check is `bun --version` (fine), but the "It failed" text
   for Step 1 says "use bun x". Works, but it is noise.

F12 [LOW] Test runs leave SQLite files in data/ (no cleanup). The page's SQLITE_CANTOPEN advice (create the folder)

F13 [LOW] Step 2 install writes skills-lock.json at the project root. This is not mentioned on the page. The skill
