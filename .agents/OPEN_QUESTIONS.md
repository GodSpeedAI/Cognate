# Open questions

1. **Dependency upgrades.** The pinned DomainForge 0.16.0 binding and other Phase 0 candidates have recorded fixture results. Which later releases preserve those results, especially DomainForge diagnostic messages (DEBT-002)? Re-run each named fixture and adapter gate before changing its pin (spec §§6, 37–39).
2. **Cordis lifecycle fit.** Does the pinned prerelease satisfy activation, dependency loss, partial setup rollback, and reverse disposal under Bun? If not, revise the engine behind the framework-owned kernel API (spec §37, Phase 0).
3. **Ledger freeze.** The candidate ledger projects the spec into 77 requirements, all implemented (AK-006 closed by RealityTrace 0.3.0 `--extensions`; AK-008 revised to the Cognate-owned UCB1 ranker, SONA rejected per ADR-0005). Freezing turns these into settled contracts; it is an operator decision. Open point before freezing: whether §22 client/bidi streaming (DEBT-004) must be proven first.
4. **Optional adapter support.** RVF, AG-UI, RealityTrace structured correlation (AK-006) and adaptive ranking (AK-008, UCB1) have implemented gates; SemanticPack still needs its named compatibility/behavior proof before a release claims it (spec §37). Its absence does not block a minimal kernel/event runtime.
