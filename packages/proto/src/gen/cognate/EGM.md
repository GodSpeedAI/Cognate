# packages/proto/src/gen/cognate — generated package namespace

## Overview

This directory is a pure output path, not authored code: it exists only because `buf generate` reproduces the proto package path `cognate/v1/...` under the chosen output root `[packages/proto/buf.gen.yaml:plugins]`. The generator writes into `src/gen` by default and mirrors the source directory structure beneath it `[packages/proto/scripts/generate.ts:outDir]`. Everything under it is emitted with a `@generated` header naming the originating `.proto` file `[packages/proto/src/gen/cognate/v1/event_pb.ts:2]`.

## Global Invariants

- The directory name is derived from the proto package path, so it must not be renamed independently of `proto/` `[packages/proto/buf.gen.yaml:inputs]`
- Nothing here is hand-edited: a fresh generation must equal the committed tree digest-for-digest `[packages/proto/test/codegen.test.ts:36]`
- Regeneration overwrites these paths in place; the output root is passed to buf as `-o` and the plugin writes relative paths beneath it `[packages/proto/scripts/generate.ts:Bun.spawn]`
- Every emitted module carries the `// @generated by protoc-gen-es v2.15.0 with parameter "target=ts"` marker `[packages/proto/src/gen/cognate/v1/runtime_pb.ts:1]`
- Consumers reach these modules through the package barrel rather than by deep import `[packages/proto/package.json:exports]`

## Global Side Effects

- Regeneration rewrites the files in this subtree, discarding any local modification `[packages/proto/scripts/generate.ts:outDir]`
- The emitted files are what `packages/proto` publishes as its `src` payload `[packages/proto/package.json:files]`
