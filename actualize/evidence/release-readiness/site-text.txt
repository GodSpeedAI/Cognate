Does this hold up for a real application? Real screen from Cognate-Workbench Evidence This app was built with Cognate. Cognate-Workbench is a working application built with Cognate. It is an agent harness for coding and general work, where AI agents write and run code, plan, and carry out tasks in conversation with you. A person scopes a task with a contract that sets its goal, limits and acceptance checks. The agent does the work, and pauses for approval before risky steps. Then a person accepts the result, or doesn't. Workbench is what was built. Cognate is what it was built from. Take it apart What Workbench is made of. Underneath the screen there are four layers: the interface you use, the agents that do the work, the capabilities they work through, and the durable record of everything that happened. Each part on the capabilities layer is a capability, a named job with one purpose. Some come straight from Cognate. Workbench built others for itself, using the same pattern. How parts fit Ask for the job by name, not for the code that does it. A capability has a stable name and version, like billing.quote@1 . Code asks for the name, not for a particular implementation. Any part that provides a compatible version can answer. Before any part runs, a permission check decides whether this caller may use it, and the default answer is no. Try it: switch the caller to mallory . The call is refused before anything runs, and the refusal is recorded. The check happens in code: see the line in packages/kernel-cordis/src/lease.ts . Real screen from Cognate-Workbench It can grow Need something new? Authorize the agent to add it. Extension is a development step you start and review.
