## 2. Framework changes surfaced by this test (why `Special case? No` is honest)

All three are recorded in `architectural-counterexamples.md`; none added a reference-named concept
(`tests/architecture/kernel-primitives.test.ts` proves no `Copilot*` primitive exists anywhere in
`packages/**/src`, and that kernel packages contain no `/copilot/i` at all).

- **C1 — caller-scoped, lease-bound remote capability offers (general repair implemented).**
  CopilotKit frontend tools register/unregister with component lifetime. Cognate had client-side
  capability *execution* (`useCapability`) but no way for a run to *discover* which remote client
  capabilities are currently offered, and no path from client registration into the server's
  eligible set (`architectural-counterexamples.md` §C1, "Why composition fails"). The repair is a
  general offer/lease mechanism: `ctx.remoteOffers` / `ctx.invokeRemoteOffer`
  (`packages/runtime-bun/src/executor.ts:335-360`), `publishRemoteOffer` /
  `listRemoteOffers` on the RuntimeService, `useRemoteCapability` / `useRemoteCapabilityHistory`
  (`@cognate/react`), durable `run.waiting` waits keyed `wait:remote:<id>` with replay-safe
  resolution after disconnect or offer expiry. Availability is revoked for new calls on unmount;
  an already-committed invocation keeps its durable continuation (R-A05's separation). The offer
  never grants authority: selection and invocation still check caller, scope, policy and contract
  version. Nothing about it is CopilotKit-specific — it is the general form of "browser offers a
  capability while mounted".
- **C2 — thread-scoped durable state with authorized CAS updates (general repair implemented).**
  CopilotKit's `agent.setState` spans runs on a thread. Cognate's `RunContext.state(id)` folded
  only the current run; `updateState` was run-addressed and rejected terminal runs
  (`architectural-counterexamples.md` §C2). The repair adds a tenant- and thread-scoped durable
  state stream with authorized read and atomic versioned updates from both caller and agent
  (`ctx.updateSharedState`, `ctx.sharedState`, caller-side thread state API with
  `expectedVersion`), folded by public projections. One committed version orders every update;
  terminal runs cannot make state inaccessible; a stale version fails without writing. This is
  the general form of "application state both sides can edit", not a chat feature.
- **A1 — live AG-UI delivery (adapter defect repaired).** The original `@cognate/ag-ui` handler
  buffered an entire run before encoding SSE. The repair follows the durable event cursor
  (`RuntimeService.events({ afterPosition, follow: true })`) with resync past resumed waits
  (`packages/ag-ui/test/live.test.ts`, `packages/ag-ui/test/reconnect.test.ts`). Domain-general:
  ordered incremental delivery is a protocol-adapter property, not a chat feature.

The DomainForge interaction model in `.sea/interaction/` is loaded in place by
`cognate/src/domain.ts` (`loadJourneyABindings`/`loadJourneyCBindings` bind
`conversation.*` and `state.*` capabilities to the model's semantic entities). The reconstruction
never copies or writes the semantic source (`tests/architecture/sea-unchanged.test.ts`).

## 3. Honesty notes

- Rows R-A13 and R-A14 are `Special case? No` — the missing parts (rename/archive/delete/paginate,
  popup chrome) are **absent on both sides' executed surfaces**, and the mechanism that does exist
  is a general projection. The gaps are recorded as `pass-with-recorded-gap` in
  `parity-report.json`, not hidden behind a bare pass.
- R-A06's mechanism is general and proven at the adapter/wire level; the browser-side per-chunk
  arg re-render is the one recorded sub-gap (see the row's note and `parity-report.json`).
- The J-D reference journey is UNCOVERED on the canonical starter (it mounts no
  `useAgentContext`; `reference-manifest.json` `uncoveredDeclared`), with
  OFFICIAL_FIXTURE_REFERENCE evidence from the pinned React-core timing suite (21/21). The
  Cognate side implements and tests the behavior (`J-D-agent-context.test.tsx`). The provenance
  mapping itself is unaffected: context-as-immutable-run-input is a composition of existing input
  semantics (`architectural-counterexamples.md` §"Context interpretation").
- No row composes by "adding a kernel primitive named for the reference". The only kernel-surface
  changes this test required are C1/C2 — both domain-general, both with general regression
  coverage (J-B/J-C journey tests, `tests/persistence/` restart/rebuild/cognition suites), both
  useful if CopilotKit ceased to exist (C1's spreadsheet-editor example, C2's incident-workspace
  example in `architectural-counterexamples.md`).
